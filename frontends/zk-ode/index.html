How It Works

      
    
        
  1. Private witness: The token marking [A, B, C] is the prover's secret. Only the MiMC hash (state root) is public.
    2. 
        
  2. ODE step: A Tsit5 (5th-order Runge-Kutta) solver computes one integration step inside a Groth16 circuit (~9,600 constraints).
    3. 
        
  3. Verification: The circuit proves: (a) the pre-marking hashes to PreStateRoot, (b) one correct Tsit5 step was computed, (c) the post-marking hashes to PostStateRoot.
    4. 
        
  4. Chain: PostStateRoot of step N = PreStateRoot of step N+1. This forms a verifiable commitment chain.
    5. 
        
  5. On-chain: Proofs are submitted to the ZkOde contract on Base L2, which verifies via the BN254 ecPairing precompile.
    6. 
      

    


    
    

      
Unconstrained Execution

      
This system has no built-in termination. Unlike discrete Petri nets that can deadlock when tokens are exhausted, the continuous ODE dynamics guarantee that every transition always has a non-zero firing rate.

      
    
        
  • No step limit: The contract has no maximum step count. Proofs can be submitted forever.
    • 
        
  • No halting state: The A → B → C cascade follows exponential decay. Concentrations approach zero asymptotically but never reach it — there is always a next valid step.
    • 
        
  • No pause or kill switch: The contract has no owner override, no pause mechanism, and no way to stop accepting proofs. Once deployed, it runs until the chain itself stops.
    • 
        
  • Conservation law: A + B + C = 1 is invariant across all steps. The circuit enforces this via the stoichiometry matrix, so no tokens are created or destroyed.
    • 
        
  • Equal rates: With k0 = k1 = 1.0 and enforceOptimal = true, either transition is a valid choice at every step (tied rates satisfy the optimality constraint).
