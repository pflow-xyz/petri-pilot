How Scores Work

Strategic values emerge from network topology, not hand-coded heuristics.

  1. The tic-tac-toe board is modeled as a Petri net: 9 cells as places, moves as transitions, win patterns as output arcs.
  2. The ODE solver applies mass-action kinetics — each transition's firing rate is proportional to the tokens in its input places.
  3. For each empty cell, a hypothetical move is placed and the resulting net is simulated. The difference in token flow toward win-places becomes the strategic score.
  4. Center scores highest (4 win patterns), corners next (3), edges lowest (2). These values arise purely from graph structure.

Contract Enforcement

The enforceOptimal modifier in ZkOde.sol iterates over all transition rates and reverts if a higher-rate transition exists.

// Enforce optimal play: chosen transition must have the highest rate
if (enforceOptimal) {
    uint256 chosenRate = publicInputs[3 + chosenTransition];
    for (uint256 t = 0; t < numTransitions; t++) {
        uint256 rate = publicInputs[3 + t];
        if (rate > chosenRate) {
            revert NotOptimalPlay(
                chosenTransition, chosenRate, t, rate
            );
        }
    }
}

The ZK proof embeds the ODE-computed transition rates as public inputs. The contract doesn't re-run the ODE — it trusts the proof and only checks that the player picked the best-scoring move.

Why This Matters

  1. No AI black box: The strategy comes from differential equations over graph topology. Every score is deterministic and reproducible.
  2. Verifiable computation: The ZK proof guarantees the ODE was computed correctly without revealing the full board state.
  3. On-chain enforcement: Smart contracts can now enforce "play optimally or forfeit" without running the AI on-chain.
  4. General pattern: Any Petri net model can be evaluated, proved, and enforced this way — not just tic-tac-toe.
